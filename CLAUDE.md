# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

ATLAS v3.0: a Vue 3 + TypeScript (strict) + Vuetify 3 + Pinia single-page app that reimplements OHDSI ATLAS. It is a stateless client: all data comes from **WebAPI v3.0** (WebAPI 2.x is not compatible). Routing is hash-based (`#/cohorts`, `#/oauth/callback`).

## Node version

CI uses Node **24.x** (`.github/workflows/*.yml`). Under Node 26, the built-in `localStorage` global hides jsdom's, so ~1,400 unit/component tests fail with `Cannot read properties of undefined (reading 'getItem')`. Run tests under Node 24 (`nvm use 24`, or `nvm use` where an `.nvmrc` exists).

## Commands

```bash
npm run dev                 # Vite on :5173, proxies /WebAPI to :8080 (override with WEBAPI_URL=...)
npm run build               # vue-tsc + vite build (prebuild regenerates tokens, vendor, route manifest)
npm run check-all           # type-check, lint, i18n:check, unit tests, build: run before pushing

npm run lint                # ESLint, --max-warnings 0 (also the husky pre-commit hook)
npm run type-check

npx vitest run path/to/file.spec.ts          # single test file
npx vitest run path/to/file.spec.ts -t "name" # single test by name
npm run test:unit           # watch mode
npm run test:coverage       # what CI runs; thresholds in vitest.config.ts (lines/statements 92, branches 86, functions 78)
npm run test:no-conditional-assertions   # static gate, blocks every PR

npm run test:e2e            # Playwright (chromium project; phenotype-library is a separate project)
npx playwright test tests/e2e/foo.spec.ts

npm run test:mutation:file -- src/path/File.vue   # Stryker on one file
npm run test:mutation:check # Stryker dry run (CI runs this on PRs); rerun after adding a component
```

Full stack (Postgres + Eunomia + WebAPI + Caddy): `docker compose -f docker-compose.dev.yml up --build`, then https://localhost (`admin`/`admin`). `docker-compose.yml` runs the released images instead. Both use the same ports, so run only one at a time.

## CI gates beyond lint/tests

`lint-typecheck.yml` also runs `i18n:check`, `tokens:check` and `routes:check`. The last two regenerate files and fail if git shows a diff, so **commit the regenerated output**:
- `src/ui/tokens.css` is generated from `src/ui/tokens.ts` (`npm run tokens:build`).
- `src/router/routes.manifest.json` is generated from `src/router/routes.ts` (`npm run generate:routes`). The extractor is regex-based: each route object must put `path:` before `name:` and use single-quoted strings. `meta.agentVisible`/`agentLabel` decide what the agent can navigate to.
- `src/plugins/host/capabilities/capabilities.manifest.json` is generated by `npm run generate:capabilities`.

## Architecture

**Bootstrap (`src/main.ts`).** The order matters: auth interceptor, plugin message bus, Pythia bridge and WebMCP are set up first. Then `loadAppConfig()` loads runtime `config-local.json` (`api.url` etc., schema in `src/config/app-config.*`). Then `plugins.json` (theme colors, chart palette, plugin list) through `PluginConfigService`, then the Vuetify/Pinia/router setup. `authStore.hydrateAuth()` must run before `router.isReady()` so the guards see the token. After mount, auth and locale initialise asynchronously, and then the plugin framework starts.

**Data layer.** `src/services/*.service.ts` wrap WebAPI endpoints through `src/services/http-client.ts`, which adds auth, locale and retries (idempotent methods only, unless opted in). They map responses with Zod and the `src/utils/*mapper*` helpers. Pinia stores (`src/stores/`) hold app state, and composables (`src/composables/use*.ts`) are the main API that views and components consume. Versioned artifacts (cohorts, concept sets, IR, pathways, characterizations) share `versions-service.factory.ts`.

**Cohort expressions** follow the OHDSI Circe JSON model. The editor UI is in `src/components/circe/` and `src/components/cohort-editor/`.

**Design system.** `src/ui/` (tokens, theme, chart config) and the `Atlas*` components in `src/components/ui/` are also published as the `@ohdsi/atlas-ui` library (`packages/atlas-ui`, `vite.lib.config.ts`, Histoire stories `*.story.vue`). Keep `src/ui` free of i18n: the host injects translations (e.g. `setChartLabelResolver`).

**Plugins (`src/plugins/`).** Plugins are single-spa parcels in SystemJS format, listed in `plugins.json`. `core/` has the loader, registry and runtime, `navigation/` has the routes, menu and mount points, and `messaging/HostMessageBus.ts` handles host↔plugin messages. The host exposes its Vuetify instance on `window.__atlasVuetify` for plugins that treat Vuetify as external. Reference plugin: `plugins-dev/hello-world-plugin`. Guide: `docs/plugin-development-with-atlas-ui.md`.

**Agent surfaces.** `src/plugins/host/capabilities/registry.ts` defines the `CAPABILITIES` (JSON-schema tools for editing cohorts and artifacts) that two clients use:
- `pythiaBridge.ts`, the Pythia assistant plugin. It puts a human in the loop: `requiresApproval` capabilities show a confirmation card.
- `webmcp/`, which registers the capabilities with `navigator.modelContext` when the browser has it. It is ungated by design (`docs/webmcp.md`).

**i18n.** `src/locales/en.json` is the source and ships in the main bundle. `ja`/`ko`/`ru`/`zh` lazy-load and fall back to English. Use `t('key')` (reactive) or `tv('key')` (plain string), and never pass an inline English fallback: `i18n:check` rejects it. The `i18n:*` scripts and `docs/i18n.md` cover syncing, renaming and pruning keys.

## Testing rules

The tests are in `tests/unit`, `tests/component` and `tests/integration` (Vitest + jsdom + Vue Test Utils, setup in `tests/setup.ts`) and `tests/e2e` (Playwright, which mocks WebAPI per page and runs in the UTC timezone for screenshot stability). `docs/testing-guide.md` is binding. The key points:
- No conditional assertions (`if (x) expect(...)` without an `else` that calls `expect.fail`) and no tautological `expect(true)`. The gate script rejects both.
- Assert on values, not existence. Don't reach into `wrapper.vm.$.setupState`. Assert translated text through the i18n key, not the English copy.
- Prove a new test has teeth (mutation score matters, not just coverage).
- Vitest 4 calls `mockImplementation` functions without `new`. Mock constructors such as `ResizeObserver` with a class, not with `vi.fn().mockImplementation(() => ({...}))`.

## Branches

The upstream PR target is `develop` on `OHDSI/Atlas3`. `chi/3.0.x` on the Center-for-Health-Informatics fork carries CHI-only files under `chi/` (image build and deploy; see `chi/README.md`). Do upstream work on branches off `develop`, not on `chi/3.0.x`.
